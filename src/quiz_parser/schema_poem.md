# 诗文赏读素材 YAML 规范（分镜×讲稿二合一）

> 用途：**仅接收古文正文作为唯一输入**；内部同时完成两件工作：①自动生成配套讲课讲稿TTS文本；②自动生成分镜绘图提示词；将讲稿、分镜画面全部整合输出为单份YAML素材包。
> 一条 `group` 对应一个分镜，包含一张绘图、配套讲稿解说。
> 核心铁律：**原文文本严格原样保留，不篡改原文；生成的讲稿要贴合原文语义，不脱离文本肆意发挥；禁止对古文原文润色、纠错、改写。**

## 1 顶层结构
顶层字段：`groups`，与poem_meta。

| 字段 | 类型 | 说明 |
|---|---|---|
| `groups` | array[object] | 分镜数组；数组顺序即为视频播放顺序，每一项代表一个独立分镜 |
| `poem_meta` | object | 诗词古文元信息 |
| `poem_meta.title` | string | 诗词古文的标题 |
| `poem_meta.author_or_source` | string | 诗词古文的作者，有时也可以是文章的出处（比如用"《》"书名号包裹） |
| `poem_meta.dynasty` | string | 诗词古文的朝代。 |
| `poem_meta.content` | String (multiline) | 原始诗词古文的正文部分 |





## 2 Group 分镜对象

每一个 `group` 代表一个分镜：**一张绘图 + 一组讲稿音频**。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `g` | string | 是 | 分镜唯一短ID，命名规则：`g0`、`g1`、`g2`……按播放顺序自增 |
| `gt` | string | 是 | 分镜检索标题，供人阅读；`g0.gt` 必须承载格式：`开篇一 · 题解｜作品名 · 朝代·作者` |
| `st` | string | 是 | 分镜阶段枚举值：`cover`开篇 / `verse`正文 / `end`结尾 |
| `sn` | integer | `verse` 必填 | 对应正文句子序号，从 1 开始计数；**同一个 `sn` 代表同一句原文的2个分镜**；输入古文正文**一行即为一句原文**；`cover`、`end` 不使用此字段 |
| `gst` | string | 否 | 朗读字幕锚点，填写对应完整原文单行文本，必须和输入古文逐字完全一致，原稿错字原样保留；`cover`、`end` 可省略该字段 |
| `a` | object | `cover`/`verse` 必填，`end` 可选 | 讲稿音频对象，承载TTS配音脚本，**讲稿由模型根据古文自动生成** |
| `a.pd` | array[object] | `a`存在则必填 | 讲稿句子数组，按配音播放顺序排列 |
| `a.pd[].txt` | string | 是 | 讲稿内容，模型生成；单行尽量简短，便于配音断句，不加入舞台提示、括号标记 |
| `a.pd[].sp` | string | 是 | 配音角色；**无特殊说明统一使用 `naiwa`；业务有特殊要求时可指定其他speaker** |
| `a.pd[].gap` | float | 是 | 本句朗读结束后停顿秒数；固定参考：原文朗读行`0.4`，白话释义行`0.2`，段落收尾总结句`0.6` |
| `i` | object | 是 | 绘图对象 |
| `i.pd` | string | 是 | 正向绘图提示词，**由模型根据古文情节自动生成**；仅描述画面内容；不写文件路径、链接、负向提示词；画风不在此字段内指定，仅填写：年代、构图视点景别、场景描述、人物（年龄地域服装表情动作）、时间、地点、环境、道具、色彩。 |

## 3 硬性编排规则
1. 整体分镜数量计算公式：`总groups数量 = 2 + 2 × N + 2`
    - `g0`、`g1`：`cover`，2个开篇封面分镜；
    - 中间`2*N`条：`verse`正文分镜；**N = 输入古文正文行数，正文一行=一句原文**；每一句原文固定生成2条group，共用同一个`sn`；sn序列严格：`1,1,2,2,3,3……N,N`；
    - 末尾倒数第2、倒数第1条：`end`，2个结尾分镜。
2. 一个`group`严格对应一个分镜：一张绘图`i.pd` + 一组讲稿`a.pd`；禁止单个group挂载多张画面。
3. 同`sn`的两条分镜强制区分：景别、视点、构图、时间至少一项明显不同。固定分工：
    - sn对应第一条group：**放置古文原句朗读**；
    - sn对应第二条group：**放置白话释义讲解**。
4. `a`字段约束：`cover`、`verse`必须配置`a`对象；**仅最后一条结尾分镜允许省略a**，实现纯画面收尾，只保留BGM/环境音；其余`end`分镜必须配置`a`。
5. 原文约束：`gst`字段必须与输入古文单行文本逐字保持原样，不做校勘改错。
6. 讲稿生成约束
    - cover阶段：生成作品题解，包含作品名称、作者朝代、体裁、整体寓言主旨定性；分两行分别给到g0、g1。
    - verse阶段：每个sn第一条a.pd生成**原句朗读文本**；同sn第二条a.pd生成**白话翻译+简易解读**，一行一意，单行不宜过长。
    - end阶段：倒数第二条end生成全文总结评述；最后一条end省略`a`。
7. 绘图提示词`i.pd`强制9要素全部写全：**年代、构图（视点/景别）、描述、人物（年代、地域、岁数、服装、表情、动作）、时间、地点、环境、道具、色彩**。
    - 禁令：禁止写画幅比例；禁止写摄像机、机位；禁止引用古文原文句子、台词字幕；禁止使用引号、书名号；禁止绘制地图舆图；人物必须写明年龄体态动作，禁止笼统写“一个古人”；一张提示词只刻画一个瞬间；同sn两条画面必须景别/视点不一样；**不设置画风关键词**。

## 4 输入输出工作流程
1. 输入：**仅有古文正文文本**，无外部讲稿、无外部prompt文件。
2. 处理步骤
    1. 将输入古文按换行切分，每一行记为1句，统计N句；
    2. 按照公式计算总group数量，生成g编号序列；
    3. cover(g0,g1)：自动生成开篇题解讲稿，自动生成两张封面分镜画面prompt；
    4. verse循环：循环N句原文，每一句生成2条group，同一sn；第一条放原句朗读，第二条放白话释义解读；分别生成两套差异化画面prompt；gst填入对应原句；
    5. end(g‑2,g‑1)：倒数第二条生成全文总结讲稿与画面；最后一条只保留画面，去掉`a`字段。
3. 输出：完整YAML，只包含顶层`groups`，无任何其他顶层key。

## 5 示范输入
### 输入古文正文（仅输入这一段）
```
多忧者
沈屯子 〔明代〕
沈屯子偕友入市，闻谈者言，杨家将穷蹙。
遂戚戚忧懑，归而忧曰：“杨家将今若是，吾家可无恙耶？”
妻慰之曰：“此乃戏说耳，非实事。”
屯子怅然。
又忧曰：“倘天坠，吾将安归？”
妻复慰譬之，乃止。
世之多忧者，大类此。
```
> 正文一共7行，N=7，groups总数 = 2 + 14 + 2 = 18条。

## 6. 演示输入

### 6.1 原文：`明代_刘元卿_两瞽_00001_.txt`

```
两瞽

刘元卿 〔明代〕

新市有齐瞽者，性躁急。
行乞衢中，人弗避道，辄忿骂曰：“汝眼瞎耶？”市人以其瞽，多不较。
嗣有梁瞽者，性尤戾，亦行乞衢中。
遭之，相触而踬。
梁瞽固不知彼亦瞽也，乃起亦忿骂曰：“汝眼亦瞎耶？”
两瞽相诟。市人讪之。
噫！己罔人亦罔，而诘责无已者，何以异于是？
```

切分为 **7 句**（`N = 7`），故 `groups` 共 `2 + 14 + 2 = 18` 条。

### 6.2 已定稿讲稿：`明代_刘元卿_两瞽_tts_*.txt`

共 17 行：开篇 2 行 + 正文 7 段 × 2 行（原文行 / 白话行）+ 末段总括 1 行。落位见 §4 模式 A。

> 注意：这份原稿本身带 OCR 错字（`两鼓`、`齐鼓`、`渠中`、`眼瞎爷`、`相触而质`、`己网人亦网`，正字应为 `瞽`、`衢`、`耶`、`踬`、`罔`）。**本 schema 不改 YAML 里的文案**，错字请在源 txt 里改好后重新入库；YAML 只负责忠实搬运当前状态。

### 6.3 已定稿提示词：`明代_刘元卿_两瞽_prompt_*.txt`

22 段 `positive`，本示范从中取 18 段与分镜一一配对（其余可留作备选镜头）。
